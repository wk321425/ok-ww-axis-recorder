# 跑轴记录（ok-ww 插件）

每打一局，把下面这些按时间记成一份 JSONL，在「跑轴复盘」页里看时间线。设置里「记录模式」有两种：

- **测试代码**（默认）：记自动战斗打的每一局，看轴代码按了什么、读到了什么
- **人为操作**：记自己手打的每一局，见下面「人为操作模式」。**选它之前要先在「触发任务」里关掉「自动战斗」**，开着它一进战斗就会接管；没关时插件会弹提示，手打不记

测试代码模式记的是：

- **按键**：所有交互后端真正发出去的键和鼠标（包括队伍代码直接调 `interaction.*` 和 `ctypes.windll.user32.SendInput` 的），带调用它的队伍代码行号
- **在场**：`in_team()` 认到的当前角色变化，HUD 消失（大招演出、过场）单独一段
- **出招**：每个角色 `perform()` 的开始和结束
- **读屏**：队伍/角色代码发起的 `find_one`、`find_feature`、`calculate_color_percentage`、`get_cd`、`get_current_con`。连续读到差不多的值合成一段（记次数、最小/最大值）。判脱战、找怪、认 HUD 这类框架例行检查不记
- **日志**：这一局里 ok 日志器打出的每一条
- **画面**：每秒 4 帧缩到 960×540 存成 JPEG；读屏结果变了的那一刻，把读的那块原图（不缩）也存下来。按热键还能导出最近几秒的原图

一局从自动战斗判进战斗开始，脱战结束。打到一半关掉「自动战斗」（包括轴代码把停止信号吞了、自动战斗出错被框架停用）、点 ok-ww 的停止（执行器暂停），这局 1~2 秒内也会收掉，结束原因写明是哪种；接着点开始的话另开一局。

文件在 ok-ww 目录的 `logs/axis_runs/`，按键读屏记录默认留最近 50 局，画面只留最近 5 局。

这是第三方插件，不是 ok-ww 官方功能。出了问题请在本仓库提 issue，不要去 ok-ww 主仓库报。

## 安装

1. 需要带插件页的 ok-ww（ok-script 2.0.15 起）。
2. 两种装法任选一种：
   - 在插件页填仓库地址 `wk321425/ok-ww-axis-recorder`，从 Release 安装，以后还能检查更新；
   - 从 [Releases](https://github.com/wk321425/ok-ww-axis-recorder/releases) 下载 `axis_recorder-<版本>.zip`，在插件页选「导入本地文件」。
3. 装好后左边多两项：「跑轴复盘」是看记录的页面；「跑轴记录」是插件的任务分组，里面是录制开关和设置（默认开着）。框架在导入插件时会先把所有自定义任务关掉，导入后到「跑轴记录」里确认开关是开的。

## 页面

- 上面选哪一局；勾着「跟随最新一局」时，打完会自动切到新的一局（只在 ok-ww 是前台窗口时刷新）
- 「分圈按」选一个角色，按它每次真正上场（从别人切过来，大招演出回来不算）切圈，摘要里给每圈时长；按队伍记住选择。没选过时默认选每圈只上场一次的角色
- 摘要只常驻一行（总时长、结束原因、分圈）；队伍版本、分辨率、HUD 不在多久、按键读屏次数、各角色统计在悬停提示里
- 下面「分圈对比」：每圈拆成依次上场的各段，格子是这一段在场多少秒；比同样上场顺序那几圈的中位数慢 1 秒以上的标橙（同顺序不到 3 圈不标），点格子时间线跳过去。选的角色每圈上场不止一次时会提示「可能是半圈」
- 时间线：Ctrl+滚轮缩放，悬停看详情（含代码位置），点一下下面的表格跳到那一刻；按住左键拖红线，右边画面跟着走，松手表格才跳过去，拖到左右边上自动滚
  - 在场：轴只在调 `in_team()` 时才看 HUD。一段里最后一次看到之后轴没再看的那截画淡，实际可能早就变了
  - HUD 淡入淡出那一帧只认到一个号码时，框架会把第一个没认到的格子当成当前角色（常误报成 1 号位）。这种帧画成点状、名字后面带「?」，分圈、在场时长、按键归属都不算它
  - 按键：同一个键 0.35 秒内接着按合成一条「×N」（切人键、R 会一直按到生效）；按下到松开不到 0.2 秒的算点按，不画成「按住」
  - HUD 不在时按的键，统计和表格里算在最后一个看到的角色头上；摘要里写「R 76(5 段)」= 按了 76 下，合成 5 段连按
- 表格：过滤框能搜角色、按键、模板名、函数名、日志内容；点一行时间线跳过去
- 顶上「打包反馈」把这一局打成 zip 发给做轴的人，见下面「打包反馈」
- 右边一列是光标那一刻的画面（不晚于光标的最后一帧），◀ ▶ 一帧一帧走，时间线和表格跟着跳
  - 光标前后 0.15 秒内读过的框叠在画面上：绿 = 找到（细框是找到的位置）、橙 = 没找到、紫 = 颜色占比、金 = 打点。没给 box 的找图按框架的算法补出搜索框（模板原位置 ± 偏差）
  - 点时间线上的读屏/打点，或者表格里的读屏行，下面显示读的那块原图（整数倍放大，不插值）。这一段里读数没变时显示之前最后一次变化存的那张

## 人为操作模式

人自己打，插件不发游戏操作的键，只看和记（开了「手打录屏」时只替你按录屏软件的快捷键）：

- **按键**：用 Raw Input 收键盘鼠标（系统抄送一份原始事件，不在输入链路上，不装钩子），带按下/松开时刻，看得出按住多久；鸣潮不在前台时不记（记一个「暂停/继续」打点），切出去和收尾时还按着的键记成松开。连点器/宏软件发的键标「SendInput」
- **在场**：插件自己每 0.25 秒读一次 HUD（和自动战斗认角色用的是同一个函数），不是按数字键推的
- **画面、热键导出原图**：和测试代码模式一样
- 不记读屏（读屏是轴代码在读，手打没有）；ok-ww 自己别的触发任务发的键照记，带代码位置

一局怎么算开始和结束：

- 自动认：HUD 在、看到锁定框或敌人血条就开局；HUD 在但连续「手打没怪几秒算打完」（默认 5 秒）没看到就结束，HUD 连续 15 秒不在也结束（大招演出、处决镜头那几秒不算）。开局前 3 秒内的按键也算进这一局
- 热键（默认 F7，可选 F6/F7/F8/Ctrl+Alt+E/不用）：按一下开始、再按一下结束，不管有没有怪；热键开的局只有再按热键才结束。和导出原图热键选成同一个时只留导出
- 另外：自动战斗被打开、切回测试代码、ok-ww 停下（执行器暂停、插件被关）超过 3 秒，这局都会收掉；一局最长 30 分钟

要求：

- ok-ww 要保持在运行（触发任务在跑），人为操作是靠这个插件的触发任务每 0.25 秒看一次画面
- Raw Input 只在人为操作模式、自动战斗关着时才登记，测试代码模式一条都不收，不影响跑轴
- 复盘页列表里手打的局前面标「[手打]」，文件名带「手打_」，和 WWKeyRecorder 记的文件格式一样、可以混着看
- 设置「手打备注」（比如「4R16居」）写进每一局的表头，复盘页摘要最前面显示；结束那行和 WWKeyRecorder 一样写按键次数、切出去几次、一共多久，结束原因写法也一样（按热键停止）

### 手打录屏（剪教学视频用）

设置「手打录屏」选 N卡 (NVIDIA App) / A卡 (AMD Adrenalin) / Win 游戏栏，插件替你按录屏软件的快捷键，打完自己找到录屏文件、和这局对上时间：

- **录屏方式**：默认「结束时存回放」——一局打完按一下存回放（N 卡/A 卡的即时重放、游戏栏的「录制所发生的事情」要开着，时长要盖过一局：N 卡默认 5 分钟够，游戏栏默认 30 秒要调长）。也可以选「开局开录、结束停」，开局按一下开始录、结束再按一下停；录屏软件没开着或快捷键不对时开和停会错位，所以默认用存回放
- **快捷键**：留空用默认。N 卡直接读 NVIDIA App 里设的（出厂 存回放 Alt+F10 / 录制 Alt+F9）；A 卡 Ctrl+Shift+S / Ctrl+Shift+E；游戏栏 Win+Alt+G / Win+Alt+R。改过的填成 `alt+f10` 这样。人还按着 Shift/Ctrl 时会等松开再按（按着 Shift 发 Alt+F10 在 N 卡上是关掉即时重放）；这几下模拟按键不记进这局
- **录屏文件夹**：留空时 N 卡读 NVIDIA App 设置里的，游戏栏是「视频\捕获」，A 卡是「视频」；往下找 3 层子文件夹（N 卡按游戏名分子文件夹）
- **对时**：先按「按键那一刻 = 片尾（存回放）/ 片头（开录）」估一个偏移，再拿插件这局存的画面和录屏逐帧比，取最像的那个，精确到一帧。比不上（录屏录的是整个桌面、估计差了 15 秒以上）就留估计值，复盘页会写明是估算。对时在后台做，一局 20 秒左右（2K 录屏），又开打了就先停下等
- 结果写在这局旁边的 `<这局>.video.json`（录屏秒 = 记录秒 + offset），表头和结束那行也记了这局的录屏设置和按了什么；复盘页摘要写「录屏 +12.34s（画面对时）」，画面上方显示光标那一刻对应的录屏时间，剪视频时拿这个时间去录屏里找。打包反馈会带上 `.video.json`，不带录屏本身
- N 卡实机验过：NVIDIA App 认插件按的 Alt+F10，存回放、找文件、对时打完一局半分钟内写好，对时精确到帧。A 卡、游戏栏还没人试过，先打一局看录屏文件夹里有没有出文件；复盘页写「没找到录屏」多半是即时重放没开

## 画面和热键导出

插件设置（左边「跑轴记录」分组）里：

| 设置 | 默认 | 说明 |
|---|---|---|
| 整局存画面 | 开 | 每秒 4 帧、缩到 960 宽（16:9 是 960×540）、JPEG。什么分辨率都先缩，一帧约 55~70KB，一分钟约 15MB，一局四五分钟约 60MB |
| 画面保留最近几局 | 5 | 只管画面；按键读屏记录还是按「保留最近几局」 |
| 存读屏那块原图 | 开 | 同一处读屏的结果翻转（找到/没找到）或数值变了才存一张，最快每 0.2 秒一张；框超过 640×360 时退而截找到的那块，都没有就不存；每局最多 6000 张 |
| 导出原图热键 | F8 | 可选 F6/F7/F8/Ctrl+Alt+E/不用。插件开着时这个键被占住，别的程序收不到 |
| 热键导出最近几秒 | 4 | 原图只在打的时候留在内存，4 秒以内任何分辨率都留够，再长受 320MB 上限管（见下表），最多 10 秒；打完 60 秒后放掉 |

按热键把最近几秒的原图存到 `logs/axis_runs/export/<时间>_<队伍>/`，文件名是这局第几秒；旁边的 `info.json` 写着对应哪一局、队伍目录、分辨率、设的秒数，和一行现成的 judge_test 命令（`judge_test.py at <队伍目录> --image ... -e "<表达式>"`，它会自己再缩到 1080 跑一遍）。导出目录只留最近 20 次；复盘页顶上的「清空导出原图」按钮写着现在导出了几次、占多大，点一下确认后一次删光（正在写的那次不动，每局的记录和低清画面也不动）。打完一局 60 秒内按也导得出来。

原图是游戏窗口实际的分辨率（截图给轴的那一帧原样存 PNG，不缩），所以内存和硬盘占用跟着分辨率走：

| 分辨率 | 一帧在内存 | 每秒（4 帧） | 默认 4 秒占内存 | 最长能留 | 导出一次（4 秒 16 张 PNG） |
|---|---|---|---|---|---|
| 1080p | 8.3MB | 33MB | 133MB | 10 秒 | 约 40MB（估） |
| 2K | 14.7MB | 59MB | 236MB | 5.5 秒 | 约 74MB（实测） |
| 4K | 33.2MB | 133MB | 530MB | 4 秒 | 约 165MB（估） |

设的秒数超过「最长能留」时只留得下最长那几秒：导出提示和 `info.json` 的 `note` 会写明设了几秒、这个分辨率一帧多大、实际只留了几秒（`ring_seconds`）。

关掉「整局存画面」就只剩热键导出和读屏小块。

画面只有轴自己取的帧：定时连点、等演出这类不读屏的时候（实机一局 18 段，0.6~2.7 秒）就没有，画面面板会写「这帧之后 x 秒轴没取画面」。插件不自己另外截图：WGC 取帧锁是不等待的，插件占着时轴那次取帧拿不到，框架会睡最多 1 秒。

画面是截图线程给轴的那一帧本身：插件只拿引用、不拷贝（WGC/BitBlt 每帧都是新数组；发现截图方式复用缓冲区才当场拷）。缩放和编码在后台线程，先从 BGRA 原数组整数倍 INTER_AREA 再线性缩到 960 宽，单核约 2.5ms 一帧，不用 OpenCV 线程池；队列满了丢最旧的，不让轴等。

## 打包反馈

复盘页顶上「打包反馈」把选中的这一局打成一个 zip，存到 `logs/axis_runs/feedback/<这局>_反馈.zip`（留最近 10 个），打好后在资源管理器里选中它。点的时候先弹一个框：写「哪里不对」（可以不填），勾不勾这局 F8 导出的原图（写着几次、多大）；手打录屏对上了的局还能勾「带上录屏」（默认不勾，录屏动辄几百 MB）。

包里有：

| 文件 | 内容 |
|---|---|
| `反馈说明.txt` | 填的「哪里不对」、这局摘要（开打时间、时长、结束原因、分圈、各角色统计）、队伍目录和版本、分辨率、ok-ww 版本、录这局的插件版本、系统 |
| `feedback.json` | 同样的信息，给程序读 |
| `ok-script_这一局.log` | ok-ww 日志里开打前 30 秒到结束后 30 秒的行（异常堆栈跟着上一行；过了午夜改名的旧日志也会找） |
| `axis_runs/<这局>.jsonl` | 这局的记录 |
| `axis_runs/<这局>.media(.idx)` | 整局画面（这局没存或已经超出保留局数就没有） |
| `axis_runs/export/…` | 这局按 F8 导出的原图（`info.json` 里记着是哪一局，按这个挑） |
| `axis_runs/<这局>.video.json` | 手打录屏的对时结果（录屏秒 = 记录秒 + offset） |
| `video/<录屏文件名>` | 勾了「带上录屏」才有，原样放进去不压缩 |

收到的人在复盘页点「打开反馈包」选这个 zip 就行，不用自己解压：插件解到 `logs/axis_runs/imported/<包名>/`（只留最近打开的 10 个），和本地记录分开放、开新局时不会被删，下拉框里标「[导入]」，摘要最前面是对方写的「哪里不对」，悬停提示里有对方的 ok-ww/插件版本和系统；带了录屏的话录屏时间直接对到解出来的那份。看导入的局时自动取消「跟随最新一局」，「打开文件夹」打开的是那个包解出来的文件夹（反馈说明、日志都在里面）。只解反馈包该有的文件（记录、画面、导出原图、录屏、说明和日志），别的东西和想跳出文件夹的路径一律跳过。

正在录的时候不让打包（会跟轴抢资源）；打包途中轴开打了，每写 1MB 歇 0.02 秒。JPEG/PNG 原样放进去不再压缩，一局带 3 次导出约 230MB，几秒打完。

## 队伍代码自己打点（可选）

自己切帧判的东西（`task.frame[...]` 裁图算颜色这类）框架补丁抓不到，可以加一行：

```python
mark = getattr(self.task, 'axis_mark', None)
if mark:
    mark('协奏光圈', glow_ok, box)
```

没装插件时 `axis_mark` 不存在，这行什么都不做，分享出去的轴不受影响。

## 开销

测试里量的（`tests/test_axis_recorder.py` 的 TestOverhead）：被包的函数不在录时每次多约 0.15µs，在录时读屏每次多约 4.3µs（含补算搜索框、判断要不要截小块；找图本身是毫秒级）、按键每次多约 1.4µs、取帧每次多约 0.2µs（每 0.25 秒那一帧多塞一次队列）。格式化和写盘在后台线程，每处理 16 条让一次 GIL；画面编码在另一个后台线程。

## 开发

- 打包：`python build.py`，输出 `dist/axis_recorder-<版本>.zip` 和 `.okscript`。它从旁边的 `../ok-ww`（[ok-wuthering-waves](https://github.com/ok-oldking/ok-wuthering-waves) 源码）import ok-script 做检查。版本号要同时改 `manifest.json` 和 `AxisRecorder.py` 里的 `PLUGIN_VERSION`。
- 测试：`python tests/test_axis_recorder.py <ok-ww 源码目录> dist/axis_recorder-<版本>.okscript`。测试读的是 dist 里的包，**改完先打包再测**。也可以用安装版自带的 Python 跑：`<ok-ww>/python/python.exe tests/test_axis_recorder.py <ok-ww>/working dist/...okscript`。
